# MenuMate 키오스크 웹페이지 디자인 의뢰서

- 작성: PM / 작성일: 2026-10-27
- 의뢰 대상: 디자이너
- 기준 문서: [`docs/00_pm_decisions.md`](../docs/00_pm_decisions.md) (결정 D1~D85). 이 의뢰서와 충돌하면 PM 결정 문서가 우선한다.
- 전시일: **2026-11-05(목)**. 최종 점검 10/31(토), 고령층 사용성 테스트 11/1~11/3.

---

## 1. 무엇을 만드는가

**한식당 매장에 놓이는 AI 주문 키오스크의 웹 화면**이다.

- 카메라로 손님의 **연령대**를 추정한다. 나이 숫자는 화면에 보이지 않고 저장도 하지 않는다.
- **55세 이상**이면 큰 글씨 화면과 음성 안내로 바뀌고, 짧은 질문 5개로 취향을 물어 메뉴 3개를 추천한다.
- 그다음 매장/포장 → 주문 확인 → 결제(시뮬레이션) → 주문번호까지 이어진다.
- 55세 미만은 일반 메뉴판을 보고, 원하면 "AI와 대화하기"로 같은 추천을 받는다.
- 추천은 공개 리뷰 70만여 건과 국민건강영양조사 통계로 학습한 엔진이 한다. 화면에는 "또래 분들이 자주 드세요", "손님 평이 좋아요" 같은 **추천 이유**가 붙는다.

**가장 중요한 성공 기준**: 55세 이상 손님이 **도움 없이 혼자** 주문을 끝내는 것, 그리고 전시 시연에서 흐름이 끊기지 않는 것.

## 2. 누가, 어디서 쓰는가

| 항목 | 내용 |
|------|------|
| 주 대상 | 55세 이상 고령층 (큰 글씨 화면) |
| 그 밖 | 55세 미만 일반 손님 (기본 화면) |
| 기기 | **21인치 모니터를 세로로 세움 (1080×1920)**, 테이블 위 공용 주문기, 터치 |
| 카메라 | 모니터 위 웹캠 (Logitech Brio 500 예정) |
| 소리 | 질문과 안내를 음성(TTS)으로 읽어 줌 |
| 환경 | 전시장. 관람객이 직접 써 보고 팀원이 옆에서 설명. **인터넷 없이** 노트북 한 대로 동작 |
| 크기 감각 | 실제 화면에서 1px ≈ 0.25mm. 32px 글자 ≈ 8mm |

## 3. 디자인 방향 (꼭 읽어 주세요)

### 지금 유지하는 방향
- **"한식당 벽 메뉴판·간판" 느낌** (D55). 흰 판 + 먹색 글씨, 쪽빛 주 버튼(#1B3A8C), 고추색 가격(#A3121A), 고른 것은 치자색(#F6C343), 사진이 없으면 옅은 오방색 카드.
- **서체: 제목 Black Han Sans, 본문 Pretendard** (D54, D70). 둘 다 프로젝트에 파일로 들어 있다.

### 이전에 거절된 시도 (반복하지 말 것)
- 2026-10-26에 "주문서(전표·영수증)" 모티프와 고정폭 서체(D2Coding)로 전체를 바꿨으나, **사용자가 실제 화면을 보고 "이전보다 못하다"고 판단해 되돌렸다** (D70).
- 그래서 이번 의뢰는 **지금 방향을 바탕으로 완성도를 높이는 것**이다. 방향 자체를 바꾸고 싶으면 시안을 만들기 전에 근거와 함께 PM에게 먼저 제안하고, 사용자 확인을 받은 뒤 진행한다.

## 4. 만들 화면

화면 흐름의 정답은 [`docs/contracts/kiosk-flow.md`](../docs/contracts/kiosk-flow.md) (v1.2)와 [`docs/contracts/v2-changes.md`](../docs/contracts/v2-changes.md) 7장이다. 화면 10개 × **큰 글씨 / 기본** 두 모드를 모두 디자인한다.

| # | 화면 | 핵심 |
|---|------|------|
| 1 | 대기 | "어서 오세요", 카메라 위치 안내, 두 버튼("큰 글씨로 주문" / "바로 주문"), 카메라 안내 문구 **항상 표시** |
| 2 | 인식 중 | 판정 중임을 부드럽게 알림. 8초 안에 안 되면 기본 화면으로 |
| 3 | 음성 질문 (5개) | 질문 문구 + 네/아니요 + "다시 듣기" / "읽어 드리는 중…", 진행 표시 "질문 n / 5", "그냥 메뉴 볼래요" |
| 4 | 추천 3개 | 사진 + 메뉴명 + 가격 + 추천 이유(최대 3개) + 담기 |
| 5 | 메뉴판 | 기본: 카테고리 탭 + 3열 / 큰 글씨: ① 종류 고르기 → ② 메뉴 4개씩 |
| 6 | 매장/포장 | 두 선택지, 같은 무게 (정답처럼 보이지 않게) |
| 7 | 주문 확인(장바구니) | 수량 +/−, 수량 1에서 "빼기" 확인, 빈 상태 안내, 합계, 결제하기 |
| 8 | 결제 중 | 시뮬레이션, 1.5초 정도 |
| 9 | 결제 실패 | 장바구니 유지, "다시 결제" / "주문 확인으로" |
| 10 | 주문번호 | 큰 번호(예: 002), 15초 뒤 처음으로, "처음으로" |

상태 화면도 함께 디자인한다: 빈 장바구니, 빼기 확인, 추천 실패, 메뉴 불러오기 실패, 서버 꺼짐.

### 질문 5개 (문구 변경 금지, 계약)
1. 매운 음식도 괜찮으세요?
2. 따뜻한 국물 요리가 좋으세요?
3. 부드러운 음식이 좋으세요?
4. 든든하게 드시고 싶으세요?
5. 담백한 맛이 좋으세요?

### 추천 이유 문구
매콤한 맛 · 순한 맛 · 따뜻한 국물 · 부드러운 식감 · 든든한 한 끼 · 담백한 맛 · **또래 분들이 자주 드세요** · **손님 평이 좋아요** · 사장님 추천

## 5. 반드시 지킬 기준

### 큰 글씨 화면 (55세 이상)
- 본문 **28px 이상**, 버튼 높이 **72px 이상**, 글자와 배경 대비 **7:1 이상** (D51). 더 크게는 가능, 줄이려면 PM 승인.
- 한 화면에서 **고르는 대상 4개 이하**, 한 화면에 한 가지 일.
- 주 버튼(쪽빛)은 화면마다 **앞으로 가는 버튼 하나**만.
- **빛 테두리** (D78): 지금 눌러야 할 버튼 1~2개의 테두리가 은은하게 빛나며 깜빡인다. **초당 3회 미만**(약 1.2초 주기, 광과민성 발작 기준), 기기의 "동작 줄이기" 설정이면 움직임 없이 테두리만.
- 화면 문구와 음성 안내가 같은 내용이어야 한다.

### 공통
- **화면에 나이 숫자 금지** (D2). 연령대 이름(예: "55세 이상")도 화면에 띄우지 않는다.
- 대기 화면의 카메라 안내 문구 상시 표시 (D20): "연령대 추정을 위해 카메라를 사용하며 영상은 저장되지 않습니다"의 뜻 유지.
- 인터넷 없이 동작 (D32): 서체·아이콘·이미지는 모두 프로젝트 파일. CDN, Google Fonts 금지.
- 메뉴 사진: 출처·라이선스가 확인된 사진만(CC0·CC BY, `backend/seed/menu-images/CREDITS.md`). 사진이 없거나 못 불러오면 색 카드 + 메뉴명 (D40, D77). 인터넷에서 받은 출처 불명 사진 금지.
- 움직임은 최소화. 누른 결과를 보여 주는 짧은 반응만.
- 판정 후 화면 상단에 모드 전환 버튼("큰 글씨로 보기" / "기본 화면으로"). 결제 중·주문번호 화면에서는 숨김.

## 6. 이미 해결한 사용성 문제 (되돌리지 말 것)

Frontend가 [`frontend/docs/usability-review.md`](../frontend/docs/usability-review.md)에 정리하고 고친 13가지다. 새 디자인에서도 해결된 상태를 유지한다.

- 메뉴를 다시 누르면 수량이 늘던 문제 → "담기" 띠, 큰 글씨는 다시 눌러도 그대로
- "네"·"매장에서 먹기"만 쪽빛이라 정답처럼 보이던 문제 → 같은 흰 버튼 + ○✕ / 그릇·봉투 그림
- 비활성 버튼이 눌러도 될 것처럼 보이던 문제 → 회색 + 점선 + 이유 문구
- 수량 1에서 "−"를 누르면 확인 없이 빠지던 문제 → "빼기" 확인
- 큰 글씨 메뉴판의 누를 곳 14개 → 두 단계로 나눔
- 그 밖: 음성과 화면 일치, 카메라 안내 글씨 크기, 터치 지연, 긴 메뉴명 말줄임
