# MenuMate 키오스크 PRD (Frontend)

- 작성: Frontend / 기준 문서: `docs/00_pm_decisions.md` (충돌하면 PM 결정이 우선)
- 상태: v1.2 (2026-10-26, kiosk-flow v1.2 반영. 디자인 방향은 디자이너 결정 D67로 바뀜, 6장은 이전 방향 기록)
- 함께 볼 것: 화면 흐름 계약 `docs/contracts/kiosk-flow.md`, 와이어프레임 `frontend/wireframes/index.html`

## 1. 목표
한식당 공용 키오스크에서 55세 이상 손님이 **도움 없이 주문을 끝낼 수 있게** 한다. 카메라로 연령대만 추정해 화면을 자동으로 바꾸고, 음성으로 취향을 물어 메뉴 3개를 추천한다. 젊은 손님은 평소처럼 메뉴판에서 고르고, 원하면 같은 추천을 받는다.

성공 기준 (D15): 전시 시연에서 인식 → 음성 질문 → 추천 → 결제 → 주문번호까지 흐름이 한 번도 끊기지 않는다. 정확도나 기능 추가보다 흐름 안정성이 우선이다.

## 2. 대상

| 구분 | 누구 | 기본 화면 | 핵심 요구 |
|------|------|----------|----------|
| 55+ (D3, D4) | 추정 연령 55세 이상 | 쉬운 화면 + 음성 안내 | 큰 글씨, 높은 대비, 한 화면에 한 가지 일, 말로 안내 |
| 55 미만 (D9) | 추정 연령 55세 미만, 판정 실패, 카메라 없이 시작 | 일반 화면 | 메뉴판에서 빠르게 고르기, "AI와 대화하기"로 추천 |
| 전시 관람객 (D30) | 매번 다른 사람이 줄 서서 체험 | 대기 화면 | 끝나면 이전 손님 정보가 남지 않음 |

오인식은 반드시 생긴다. 그래서 모든 화면에서 사람이 직접 모드를 바꾸거나 질문을 그만둘 수 있어야 한다 (D16, D17).

## 3. 핵심 사용자 흐름

```
대기 ──(얼굴 보임)──▶ 인식 중 ──55+──▶ 음성 질문 4개 ──▶ 추천 3개 ─┐
  │                    │ 55 미만 / 8초 초과                         │
  │                    ▼                                           ▼
  └──(화면 터치)──▶ 메뉴판 ◀──"그냥 메뉴 볼래요"── 질문     주문하기
                      │ "AI와 대화하기" → 질문 4개 → 추천        │
                      ▼                                           ▼
                  주문하기 ──▶ 매장/포장 ──▶ 장바구니 ──▶ 결제 ──▶ 주문번호 ──(10초)──▶ 대기
                                                       └ 실패 → 다시 결제 / 장바구니로
```

정확한 전이는 `kiosk-flow.md` 2장 전이표를 따른다.

## 4. 화면별 요구사항

| # | 화면 | 꼭 있어야 하는 것 | 하지 않는 것 |
|---|------|------------------|-------------|
| 1 | 대기 (idle) | "어서 오세요", "큰 글씨로 주문"(쉬운 화면 질문) / "바로 주문"(메뉴판) 두 버튼으로 시작(그 밖의 터치는 무시, v1.2), 하단 카메라 안내 문구 상시 (D20). 서버가 꺼져 있으면 "잠시 후 이용해 주세요"와 5초마다 재확인 | 카메라 영상 미리보기 |
| 2 | 인식 중 (detecting) | 준비 중 안내, 진행 표시(확정 프레임 수), 대기 화면과 같은 시작 버튼 두 개 | 나이 숫자, 연령대 글자 표시 |
| 3 | 음성 질문 (survey) | 질문 번호 n/4, 질문 문구(서버에서 받음), TTS로 읽기, "다시 듣기", 큰 "네"/"아니요", "그냥 메뉴 볼래요", "이전"(1번 질문에는 없음, v1.2). 4번째 답 뒤 "추천 메뉴를 고르고 있어요" | 질문 문구를 코드에 박기 |
| 4 | 추천 (recommend) | 메뉴 3개(사진 또는 색 카드, 이름, 가격, 추천 이유 문구), 누르면 담김, 담은 개수 표시, "다른 메뉴 보기", 하단 합계와 "주문하기" | 점수 숫자 표시 |
| 5 | 메뉴판 (menu) | "AI와 대화하기", 카테고리 탭, 메뉴 타일(누르면 담김), 하단 합계와 "주문하기". 쉬운 화면은 한 번에 4개씩 "앞 메뉴/다음 메뉴" | 메뉴 옵션 |
| 6 | 매장/포장 (order_type) | "드시고 가세요? 포장하세요?", 큰 버튼 2개 (D42) | |
| 7 | 장바구니 (cart) | 매장/포장 표시, 메뉴별 수량 −/+ (1~9, 0이면 삭제), 합계, "결제하기", "메뉴 더 담기". 다 비우면 "담은 메뉴가 없어요" + "메뉴 담으러 가기" (v1.2) | |
| 8 | 결제 중 (paying) | 진행 표시, "결제하고 있어요" | 버튼 |
| 9 | 결제 실패 (pay_failed) | 서버가 준 실패 이유, "담은 메뉴는 그대로 있어요", "다시 결제하기", "장바구니로" | 장바구니 비우기 |
| 10 | 주문번호 (done) | 3자리 주문번호 크게, TTS로 번호 안내, 남은 초 표시(15초, v1.2), "처음으로" | |

판정 뒤 화면 상단 띠에 매장 이름과 "큰 글씨로 보기" / "기본 화면으로"를 둔다. 결제 중·주문번호 화면은 모드 전환 없음 (v1.2).

## 5. 쉬운 화면 기준 (RULES 4장)
- 본문 글자 28px 이상 (구현: 36px), 버튼 높이 72px 이상 (구현: 108px)
- 대비 7:1 이상 (구현 색: 바탕 위 먹색 19:1, 흰 글자 위 쪽빛 버튼 10:1, 가격 고추색 7.7:1)
- 한 화면 선택지 4개 이하: 메뉴판은 메뉴 카드 4개씩, 질문은 네/아니요 2개, 매장/포장 2개. 카테고리 탭은 이동용이라 제외하되 높이 72px·글자 28px 이상, 최대 6개 (PM 결정)
- 한 화면에는 한 가지 일만 시킨다
- 쉬운 화면과 일반 화면은 **같은 컴포넌트**를 쓰고 크기 토큰만 바꾼다 (`data-mode`)

## 6. 디자인 방향
- 모티프: 한식당 벽 메뉴판과 간판. 흰 판에 먹색 글씨, 위에는 검은 간판 띠.
- 색: 바탕 `#F1F3F4`, 판 `#FFFFFF`, 먹 `#000000`, 쪽빛(주 버튼) `#1B3A8C`, 고추색(가격·오류) `#A3121A`, 치자색(담김·선택) `#F6C343`. 사진이 없으면 오방색을 옅게 한 카드 (D40).
- 서체: 제목·질문·주문번호는 간판 글씨 Black Han Sans, 본문·가격은 Pretendard. 둘 다 프로젝트에 포함 (OFL, D32).
- 정렬: 읽는 글은 왼쪽 정렬, 대기·주문번호처럼 한 가지만 보여 주는 화면만 가운데.
- 움직임은 인식 중 원과 결제 중 표시만. `prefers-reduced-motion`이면 멈춘다.

## 7. 예외 처리 (kiosk-flow 3장)
| 상황 | 처리 |
|------|------|
| 카메라 권한 거부·카메라 없음·모델 로드 실패 | 화면 오류 없이 대기 화면의 두 버튼으로 시작. 콘솔에만 기록. 시연 단축키는 계속 동작 |
| 모델 로딩 중 (수백 MB) | 대기 화면은 바로 보이고 터치·단축키·음성 안내가 동작. 모델이 준비되면 카메라 판정을 시작 |
| 판정 전 추론 오류 (`inference_failed`) | 8초 타임아웃과 같이 일반 메뉴판 (kiosk-flow v1.1). 판정 후에는 무시 |
| 8초 안에 판정 실패 | 일반 메뉴판, 상단 "쉬운 화면으로 보기" (D16) |
| TTS 없음 | 글자만 보여 주고 "다시 듣기" 숨김 |
| API 실패 | 서버 `error.message`를 크게, "다시 시도". 추천 실패는 메뉴판으로 보내고 알림 |
| 결제 실패 | 장바구니 유지, 같은 주문으로 재시도. 장바구니를 바꾸면 새 주문 |
| 초기화 뒤 늦게 온 응답 | 버린다 (새 손님 화면을 바꾸지 않음) |
| 무입력 60초, 주문번호 15초 | 대기 화면, 연령·취향·장바구니 삭제 (D30, v1.2) |

## 8. 개인정보 (D2, D47)
- 카메라 영상은 보이지 않는 video 요소로만 받아 AI 모듈에 넘긴다. 저장·업로드·로그 없음.
- 상태에는 연령대(`senior`/`non_senior`/`undecided`)만 둔다. 나이 숫자는 받지도 않는다.
- 연령대와 화면 모드는 어떤 API 요청에도 넣지 않는다 (테스트로 고정).

## 9. 범위
