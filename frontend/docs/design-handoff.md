# 디자인 반영 안내 (Frontend → Designer)

- 작성: Frontend / 상태: 2026-10-26, 디자이너 회의 준비용
- 목적: 디자인 시안을 코드에 옮길 때 무엇이 어디에 있고, 무엇이 쉽고 어려운지 알린다 (D60, D63)

## 1. 디자인 값이 있는 곳

| 바꾸려는 것 | 파일 | 비고 |
|------------|------|------|
| 색, 글자 크기, 버튼 높이, 간격, 모서리, 선 굵기, 움직임 시간 | `frontend/src/styles/tokens.css` | 이 파일만 고치면 모든 화면에 반영된다. 쉬운 화면 값은 `[data-mode='easy']` 블록 |
| 서체 | `tokens.css`의 `--font-body`, `--font-display` + `src/styles/fonts.ts` | D2Coding으로 바꿀 때 이 두 곳 (5장) |
| 화면 문구, 음성 안내(TTS) 문장 | `frontend/src/kiosk/copy.ts` | 화면 컴포넌트에는 한국어 문장이 없다 (테스트로 검사). 질문 4개 문구만 서버에서 받는다 |
| 쉬운/일반 모드 배치 규칙 (메뉴판 한 화면 카드 수, 설명 표시) | `frontend/src/styles/layout.ts` | 지금: 쉬운 화면 4개씩 넘기기, 일반 화면 전체 스크롤 |
| 컴포넌트 모양 (어떤 토큰을 어디에 쓰는지) | `frontend/src/styles/global.css` | 숫자·색을 직접 쓰지 않고 토큰만 쓴다 (테스트로 검사) |
| 화면 배치 (무엇이 어떤 순서로 놓이는지) | `frontend/src/screens/*.tsx` | 화면 10개, 파일 하나에 화면 하나 (결제 3화면은 한 파일) |
| 아이콘 | `frontend/src/components/common.tsx` (인라인 SVG) | 아이콘 파일을 주면 같은 방식으로 넣는다 |

토큰 이름은 쓰임새로 지었다(`--color-primary`, `--color-price`, `--color-selected`). 색이 바뀌어도 이름은 그대로 둘 수 있다.

## 2. 쉬운 화면과 일반 화면
- 두 모드는 **같은 컴포넌트**를 쓴다. 화면 맨 바깥 요소의 `data-mode="easy" | "normal"`에 따라 `tokens.css` 값만 바뀐다.
- CSS로 표현할 수 없는 차이(한 화면 카드 수 등)만 `layout.ts`에 있다.
- 그래서 "쉬운 화면에서만 크기·색·간격이 다르다"는 쉽다. "쉬운 화면에서만 요소의 순서나 구성이 완전히 다르다"는 화면 파일에 분기를 넣어야 해서 조금 더 든다.

## 3. 바꾸기 쉬운 것 (반나절 이내)
- 색, 글자 크기·굵기, 간격, 모서리, 버튼 높이, 선 굵기: `tokens.css`
- 문구, 음성 안내 문장: `copy.ts`
- 한 화면 안의 요소 순서, 정렬, 크기 비율, 보이기/숨기기
- 메뉴 카드 열 수, 한 화면 카드 수
- 버튼 모양(채움/테두리/투명), 눌림·비활성 상태 색
- 아이콘 추가·교체 (SVG로 받으면 가장 빠름)

## 4. 어렵거나 다른 사람의 결정이 필요한 것
| 항목 | 이유 | 대안 |
|------|------|------|
| 화면 순서·화면 추가·버튼이 가는 곳 바꾸기 | 화면 전이표(`docs/contracts/kiosk-flow.md`)가 바뀐다. PM 승인 필요 | 같은 화면 안에서 배치만 바꾸는 방향 |
| 질문 문구, 질문 수, 답 종류 | 서버(Backend)와 추천 점수 계약(`questions.md`)이 정한다 | 화면 표시 방식(글자 크기, 진행 표시)은 자유 |
| 카메라 영상 미리보기, 얼굴 테두리 표시 | 얼굴 영상은 화면에도 보이지 않게 하고 있다 (D2). PM 승인 필요 | 지금처럼 진행 표시(점 5개)로 인식 중임을 알림 |
| 나이·연령대 표시 ("55세 이상으로 보여요") | 나이 숫자 표시 금지 (D2) | "보기 편한 화면으로 바꿨어요" 같은 문장 |
| 긴 애니메이션, 화면 전환 효과 | 고령층 기준으로 최소화 (design/RULES 4장). 기술적으로는 가능 | 누른 결과를 보여 주는 짧은 반응 |
| 메뉴 사진 | 실데이터 사진은 10/31 이후. 없으면 색 카드 (D40) | 사진 있음/없음 두 상태를 모두 시안에 |
| 1080×1920이 아닌 배치 | 캔버스 크기는 고정 (D25). 작은 창에서는 통째로 축소 | 1080×1920 기준으로만 그리면 됨 |

## 5. D2Coding 서체 넣는 방법 (D62, 함께 정할 것)
D2Coding은 Regular·Bold 두 굵기이고 SIL OFL 라이선스다. 인터넷 없이 동작해야 하므로 파일을 프로젝트에 넣는다 (D32).

| 방법 | 장점 | 단점 |
|------|------|------|
| A. npm 패키지 `d2coding` (OFL, 제3자가 묶은 패키지) | 설치 명령 하나, 다른 서체와 같은 방식 | 원 배포처가 아님. 패키지가 58MB(여러 형식 포함, 빌드에는 쓰는 woff2만 들어감) |
| B. 네이버 공식 배포 파일(github.com/naver/d2codingfont)에서 woff2를 만들어 `frontend/src/assets/fonts/`에 커밋 | 출처가 분명함, 저장소에 몇 MB만 추가 | 내려받기와 변환을 한 번 해야 함 |

Frontend 추천: **B**. 출처가 분명하고 오프라인 전시에서 의존성이 하나 줄어든다. 결정되면 `fonts.ts`와 `--font-body`, `--font-display`만 바꾸면 되고, 그때 화면 겉모습이 바뀐다. 지금은 바꾸지 않았다.

주의: D2Coding은 고정폭(코딩용) 서체라 같은 글자 크기에서 한글 줄 길이가 지금보다 길어진다. 큰 제목(대기 화면 "어서 오세요" 230px, 주문번호 300px)과 버튼 문구가 줄바꿈되는지 시안에서 확인이 필요하다.

## 6. 시안을 받을 때 있으면 좋은 것
- 토큰 표: 색(이름과 hex), 글자 크기 단계, 간격 단계, 모서리, 선 굵기. 쉬운/일반 값 따로.
- 화면별 시안: 화면 10개 × 쉬운/일반. 상태(기본·눌림·비활성·오류·담김)도.
- 문구 표: 화면 문구와 TTS 문장을 `copy.ts`의 항목 이름과 맞춰 주면 바로 옮길 수 있다.
- 지금 화면은 `frontend/wireframes/index.html`(와이어프레임)과 `frontend/docs/screenshots/`에서 볼 수 있다.

## 7. 구현 방식
- 시안을 받으면 테스트를 먼저 쓰고(문구·상태·접근성 이름) 구현한다.
- 구현 후 디자이너 검수를 받는다. 다른 점은 목록으로 받아 고친다.
- 화면 흐름(어떤 버튼이 어디로 가는지)은 리듀서 테스트 47개, 앱 흐름 테스트 12개가 지킨다. 겉모습을 바꿔도 흐름이 깨지면 테스트가 실패한다.
