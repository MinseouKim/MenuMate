# Frontend 규칙

기준 문서: [`docs/00_pm_decisions.md`](../docs/00_pm_decisions.md). 이 문서와 충돌하면 PM 결정이 우선한다. 괄호 안 번호(D00)는 그 문서의 결정 번호다.

## 1. 담당 산출물
1. **PRD**
2. **와이어프레임 (Figma)**: 아래 3장의 화면 전부. 쉬운 화면과 일반 화면을 각각 그린다.
3. **키오스크 웹 앱**
4. 주관 계약: `docs/contracts/kiosk-flow` (화면 상태 흐름)
5. 공동 작업: 환경 변수 관리 가이드, 시스템 아키텍처 구상도의 프론트 부분

## 2. 기술 스택 (D34)
- React + TypeScript + Vite
- 실행: Chrome 키오스크 모드(전체 화면)
- 상태 관리: 프로토타입 `frontend/prototype/flow-logic-PROTOTYPE.html`의 `Kiosk` 순수 로직 모듈을 옮겨 쓴다. DOM 코드는 옮기지 않는다.
- AI 추론 모듈(`ai/`)과 TTS는 브라우저에서 import해서 호출한다. 직접 모델을 다루지 않는다.

## 3. 화면 목록과 흐름 (D9, D26, D29)
1. **대기**: 카메라 안내 문구 상시 표시 (D20). 터치하면 카메라 없이도 일반 메뉴판으로 간다.
2. **인식 중**: 8초 안에 확정되지 않으면 일반 화면으로 (D16)
3. **음성 질문** (질문 4개): TTS로 읽고 큰 "네/아니요" 버튼으로 답한다 (D28). 모든 단계에 "그냥 메뉴 볼래요"를 둔다 (D17).
4. **추천 3개**
5. **메뉴판**: 55세 미만 기본 화면. "AI와 대화하기" 버튼이 있다 (D9, D19).
6. **매장/포장 선택**: 장바구니 직전 (D42)
7. **장바구니**: 수량 변경 (메뉴 옵션은 없음)
8. **결제 시뮬레이션**: 성공/실패. 실패 시 장바구니를 유지한다.
9. **주문번호**: 10초 후 대기 화면으로 (D30, D43)

정확한 전이는 [`docs/contracts/kiosk-flow.md`](../docs/contracts/kiosk-flow.md)를 따른다.

## 4. 화면 규칙
- 기준 해상도는 **세로 1080×1920** (D25). 전시 때는 21인치 모니터를 세워 쓰므로 실제 모니터에서 글자 크기를 확인한다 (D31). 노트북에서는 세로 영역을 가운데에 띄운다.
- **쉬운 화면(55+)**: 본문 글자 최소 28px, 버튼 최소 높이 72px, 대비 7:1 이상, 한 화면에 선택지 4개 이하, 한 화면에는 한 가지 일만 시킨다.
- 쉬운 화면과 일반 화면은 같은 컴포넌트를 쓰고 크기 설정만 바꾼다.
- 일반 화면 상단에 "쉬운 화면으로 보기", 쉬운 화면 상단에 "일반 화면으로 보기"를 항상 둔다.
- 무입력 60초 후 대기 화면으로 돌아가고, 연령·취향·장바구니를 모두 지운다 (D30).

## 5. 전시와 시연 (D24, D30)
- "55세 이상 강제 인식"은 **키보드 단축키로만** 둔다. 화면에 개발용 버튼을 노출하지 않는다.
- 정상 흐름을 화면 녹화한 백업 영상을 11/5 전까지 만든다.
- 인터넷 없이 동작해야 한다 (D32). 웹폰트, 아이콘, 이미지를 CDN에서 불러오지 않고 프로젝트에 포함한다.

## 6. 데이터와 개인정보 (D2)
- 얼굴 이미지는 저장하지 않는다. `localStorage`, `IndexedDB`, 서버 업로드, 콘솔 로그 모두 금지.
- 카메라 프레임은 AI 모듈에 넘기고, 받은 결과(`is_senior` 등)만 상태에 보관한다.
- 원본 나이 숫자는 화면에 표시하지 않는다.

## 7. 인터페이스 규칙
- API, 메뉴 JSON, AI 출력, 질문 목록은 `docs/contracts/`의 계약만 따른다. 필드를 임의로 추가하거나 바꾸지 않는다 (D37).
- 메뉴명, 가격, 사진을 코드에 박지 않는다. 더미와 우루루 실데이터가 같은 스키마로 들어온다 (D12, D33).
- 결제는 `pay(order) → success | fail` 인터페이스 뒤에 숨긴다. 지금은 시뮬레이션 구현체를 쓴다 (D13).
- 환경 변수는 `.env`에서만 읽는다. `.env`는 커밋하지 않고 `.env.example`만 커밋한다.

## 8. 프로토타입
- `frontend/prototype/`의 파일은 버려질 코드다. 운영 코드에서 import하지 않는다.
- 현재 프로토타입에는 D16(8초 타임아웃), D17(질문 이탈), D26(매장/포장, 수량)이 아직 반영되어 있지 않다. 로직을 옮길 때 이 결정들을 함께 넣는다.
