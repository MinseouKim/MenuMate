## 0. 한 줄로

> **MenuMate**는 우루루 평촌본점 키오스크 안에 **말로 주문을 도와주는 AI 직원**을 담았습니다. 손님이 말하면 듣고, 몇 가지만 다정하게 묻고, **손님이 한 말과 실제 리뷰를 근거로** 메뉴를 추천합니다.

영상을 본 사람이 기억해야 할 것은 세 가지뿐이다.

1. **말로 하면 된다**: 버튼을 찾지 않아도 된다. 말하면 바로 듣고, 직원이 말하는 중에 끼어들어도 멈추고 귀를 기울인다.
2. **추천에 이유가 있다**: "손님이 '매운 건 못 먹어요'라고 하셔서", "리뷰: 짜장이 달지 않고 깔끔해요".
3. **틀리지 않게 만들었다**: 가상 손님 1,000명을 설계해 대화 시험 504건을 자동 채점했고, 자동 테스트 555개가 모두 통과한다. 재료를 모르면 추천하지 않고 직원을 부른다.

## 2. 기획 & 스크립터

### 2-1. 대화 내용 구조화하는 방법

시연의 주인공은 손님과 AI 직원의 **대화**다. 대본을 쓰기 전에 대화를 아래 순서로 구조화한다.

1. **실제 대화를 먼저 녹화한다.** AI 답은 매번 조금씩 달라진다. 대본에 직원 대사를 지어 넣지 말고, 로컬 키오스크에서 실제로 나눈 대화를 녹화한 뒤 그 원문을 그대로 쓴다. 로컬 서버는 대화를 `eval/live/raw/<날짜>.jsonl`에 기록하므로 녹화본과 대사를 맞춰 볼 수 있다.
2. **대화를 "비트(beat)"로 쪼갠다.** 한 비트 = 손님 한 마디 + 직원 한 마디. 비트마다 아래 표를 채운다.

   | 칸 | 쓰는 내용 |
   |---|---|
   | 비트 번호 | B1, B2 … |
   | 손님 말 | 실제로 한 말 그대로 |
   | 직원 말 | 실제 AI 답 그대로 (고치지 않음) |
   | 화면 변화 | 보드의 어떤 칸이 채워지는지, 버튼이 어떻게 바뀌는지 |
   | 보여 줄 기능 | 따뜻한 반응 / 질문 하나씩 / 보드 채움 / 끼어들기 / 재질문 등 |
   | 살릴지 | 살림 · 줄임 · 뺌 |

3. **기능 하나에 비트 하나.** 같은 기능이 두 번 나오면 하나는 뺀다. 3분 안에 대화 비트는 **4~5개**가 한계다.
4. **반드시 들어갈 장면 5개를 먼저 고정한다.**
   - 가게 첫인사 "우루루 평촌본점에 어서 오세요! 몇 분이서 오셨어요?"
   - 손님 말에 대한 따뜻한 첫 반응 (예: "생일 축하드려요! 네 분이서 오셨군요, 반가워요.")
   - **끼어들기**: 직원이 말하는 중에 손님이 말하면 직원 음성이 바로 멈춘다
   - 주문 확인 보드의 칸이 하나씩 ✓로 채워지는 장면
   - 추천 결과의 "손님이 한 말" 인용과 리뷰 한 줄
5. **대화 시나리오는 하나로 통일한다.** 추천 시나리오(오늘 실제 Gemini로 확인한 대화, 녹화 때는 그날의 실제 답을 쓴다):

   | 비트 | 손님 | 직원 (2026-11-03 실제 답 예시) | 보여 줄 기능 |
   |---|---|---|---|
   | B0 | – | 우루루 평촌본점에 어서 오세요! 몇 분이서 오셨어요? | 가게 첫인사 |
   | B1 | 생일이라 넷이 왔어요 | 생일 축하드려요! 네 분이서 오셨군요, 반가워요. 매운맛은 어떻게 해 드릴까요? | 따뜻한 반응, 인원 칸 ✓ |
   | B2 | 조금 매운 건 괜찮아요 | 생일날 매콤한 맛도 괜찮으시군요! 알레르기나 채식으로 못 드시는 재료 있으세요? | 질문 하나씩 |
   | B3 | (직원 말 도중에) 새우는 빼 주세요 | 새우를 빼고 골라 볼게요. 면, 밥, 요리 중에 어떤 걸로 먼저 볼까요? | **끼어들기**, 재료 칸 ✓ |
   | B4 | 같이 나눠 먹을 요리요 | …로 골라 봤어요. 맛있게 드세요! | 추천 결과로 전환 |

   예비 시나리오(짧게 쓸 때): "네 명 이상이에요" → "네 분 이상이시군요, 반가워요! 정확히 몇 분이세요?" → 버튼이 4·5·6·7명 이상으로 바뀌는 장면.

### 2-2. 나레이션 대본 (약 620자, 2:50)

- 말하는 속도: 1초에 4~4.5글자. 문장은 짧게, 끝은 "~습니다/~요"를 섞어 딱딱하지 않게.
- 키오스크가 직접 말하는 구간(시연)은 **나레이션을 비워 둔다.** 키오스크 목소리가 곧 주인공이다.
- 숫자는 아래 "확인된 숫자"만 쓴다.

### 2-3. 시각적 콘티 설계하는 방법

1. **콘티는 칸 하나 = 3~6초.** 2:50이면 35~45칸이다. 칸마다 아래 6가지를 적는다.

   | 칸 | 쓰는 내용 |
   |---|---|
   | 시간 | 0:48~0:53 |
   | 화면 | 무엇이 보이는지 (그림 한 장 + 설명 한 줄) |
   | 카메라·움직임 | 고정 / 확대 120% / 왼쪽→오른쪽 이동 |
   | 글자 | 화면에 뜨는 큰 글자, 자막 |
   | 소리 | 나레이션 · 키오스크 음성 · BGM 변화 · 효과음 |
   | 소스 | 녹화 파일 이름, 그래픽 번호 (5장 목록과 맞춤) |

2. **세로 화면을 가로 영상에 넣는 틀을 먼저 정한다.** 키오스크는 세로(1080×1920)다. 기본 틀은 **왼쪽 40%에 키오스크 기기 목업 + 화면 녹화, 오른쪽 60%에 큰 글자·설명**이다. 시연 중 중요한 순간(보드 ✓, 추천 이유)만 화면 전체로 확대한다.
3. **같은 기능은 같은 자리에.** 직원 말은 항상 화면 위쪽 말풍선, 손님 말은 아래쪽. 보는 사람이 눈을 옮기지 않게 한다.
4. **콘티 그림은 대충 그려도 된다.** 사각형과 화살표면 충분하다. 대신 **글자 크기와 위치**는 정확히 적는다. 편집자가 그대로 따라 한다.
5. **시간 검증**: 나레이션을 휴대폰으로 가녹음해 콘티에 붙여 보고, 3:00을 넘으면 시연 비트부터 하나씩 뺀다(문제·검증 구간은 줄이지 않는다).

## 3. 모션 그래픽 디자이너 / 편집자

### 3-1. 키프레임 애니메이션

| 대상 | 방법 | 값 |
|---|---|---|
| 들어오는 요소 (말풍선, 글자, 카드) | 아래에서 위로 + 투명도 0→100 | 이동 24px, **8~10프레임**, ease-out (속도 그래프 끝을 부드럽게) |
| 나가는 요소 | 투명도 100→0, 이동 없음 | 6프레임, ease-in |
| 보드 칸 채움 (✓) | 칸 배경색 전환 + ✓ 크기 0→110→100% | 12프레임, 살짝 튀는 overshoot 한 번만 |
| 말풍선 팝 | 크기 92→100% + 투명도 | 8프레임 |
| "듣고 있어요" 표시 | 금색 원이 숨 쉬듯 커졌다 작아짐 | 1초 주기 반복, 크기 100↔108% |
| 숫자 (504, 555, 1,000) | 0에서 올라가는 카운트업 | 0.8초, 끝에서 느려지게 |
| 화면 확대 (UI 클로즈업) | 위치·크기 키프레임 두 개만 | 120~160%, 0.6초, ease-in-out |

- **규칙**: 한 화면에서 동시에 움직이는 것은 **두 개까지**. 모든 것이 움직이면 아무것도 안 보인다.
- 키오스크 화면 녹화 위에 그래픽을 얹을 때는 **녹화된 UI의 움직임과 박자를 맞춘다**(보드 칸이 실제로 채워지는 프레임에 ✓ 강조를 넣음).
- UI 확대 장면에는 모션 블러를 끈다. 글자가 번지면 읽히지 않는다.

### 3-2. 타이포그래피

| 용도 | 서체 | 크기 (1080p 기준) | 색 |
|---|---|---|---|
| 제목·핵심 한마디 ("말 한마디로") | **Black Han Sans** | 96~140px | 금색 `#e8b23a` 또는 아이보리 `#fffbf2` |
| 설명 글자, 숫자 라벨 | **Noto Sans KR** Bold | 44~56px | 먹색 `#1c1210` / 아이보리 |
| 자막 | Noto Sans KR Bold | 48px, 한 줄 16자 안팎, 두 줄까지 | 흰 글자 + 옻칠색 `#2a1510` 80% 바탕 띠 |
| 출처 표기 | Noto Sans KR Regular | 24px | 아이보리 70% |

- 두 서체만 쓴다. 키오스크 화면과 같은 서체라 영상과 실물이 한 브랜드로 보인다(두 서체 모두 OFL 무료 라이선스).
- 핵심 문장은 **단어 단위로 나타나게**(키네틱 타이포). 단, 한 문장에 강조는 한 단어만 (예: "말 **한마디**로").
- 고령 관객도 고려해 자막은 크게, 대비는 높게. 화면 아래 15% 안쪽(안전 영역)에 둔다.

### 3-3. 컷 편집

1. **BGM 박자에 컷을 맞춘다.** 구간이 바뀌는 컷(①→②, ②→③ …)은 강박(마디 첫 박)에, 시연 안의 작은 컷은 자유롭게.
2. **J컷·L컷으로 이어 붙인다.** 다음 장면의 키오스크 소리를 0.3~0.5초 먼저 들려주고(J컷) 화면을 넘기면 대화가 끊기지 않고 이어진다.
3. **시연의 기다리는 시간 처리 — 정직하게.** AI가 생각하는 1~2초를 모두 자르면 실제보다 빨라 보인다. **한 번은 자르지 않은 실제 속도 그대로** 보여 주고, 나머지에서 대기를 줄일 때는 화면 구석에 작게 "대기 시간 편집"을 표시한다.
4. **끼어들기 장면은 컷 없이 한 테이크로.** 직원 음성이 손님 말에 바로 멈추는 것이 핵심이라, 잘라 붙이면 증거가 되지 않는다.
5. **한 장면 3~6초**, 통계·숫자 화면은 읽을 시간을 위해 최소 3초.
6. **전환 효과는 두 종류만**: 일반 컷, 구간이 바뀔 때 회문 띠가 가로로 지나가는 와이프(5장 그래픽 G1). 회전·큐브 같은 화려한 전환은 쓰지 않는다.
7. **색 보정**: 화면 녹화는 손대지 않는다(실제 색 그대로). 실사 촬영만 따뜻한 쪽(색온도 +200~300K)으로 맞춘다.
8. 최종 길이를 **3:00 이하**로 확인하고, 앞 0.5초·뒤 1초 여유를 둔다.

## 5. 성우 & 사운드 디자이너

### 5-1. 목표 톤

**적당히 신나고, 이야기가 끊기지 않게.** 문제 구간은 차분하게 시작해, 제목에서 밝게 열리고, 시연에서는 키오스크 목소리가 주인공이 되도록 한 발 물러서고, 마무리에서 따뜻하게 닫는다. 우리 목적은 **"누구나 말 한마디로 주문할 수 있게"** 이다. 기술 자랑보다 **편안함과 믿음**이 먼저 들려야 한다.

### 5-2. 나레이션 녹음

- **목소리**: 20~30대의 밝고 차분한 목소리. 키오스크 AI 직원 목소리(Google TTS `ko-KR-Chirp3-HD-Leda`, 밝은 여성 목소리)와 **겹치지 않게**, 나레이션은 다른 결(예: 중저음의 다른 성별 또는 더 차분한 톤)로 정해 둘이 구분되게 한다.
- **말투**: 웃으면서 읽는다(입꼬리를 올리면 소리가 밝아진다). 문제 구간은 반 톤 낮게, 제목부터 반 톤 밝게.
- **속도**: 1초에 4~4.5글자. 쉼표에서 0.3초, 문장 끝 0.6초 쉰다. 숫자("세 배", "55.5%", "555개")는 한 박자 천천히.
- **녹음 환경**: 48kHz / 24bit WAV, 마이크와 입 15~20cm, 팝 필터, 옷장·커튼 앞처럼 울림 없는 곳. 녹음 시작 전 **방 소음 5초**를 따로 녹음(잡음 제거용).
- **테이크**: 문장마다 3번씩, 잘된 것에 표시. 한 번에 길게 읽지 않는다(편집에서 문장 단위로 박자를 맞춰야 함).
- **레벨**: 말소리 최고점 -6dBFS 근처, 절대 0dB를 넘기지 않는다.
- 후처리 순서: 잡음 제거(약하게) → EQ(80Hz 아래 자르기, 3~5kHz 살짝 올려 또렷하게) → 컴프레서(2~3:1) → 디에서(ㅅ·ㅆ 소리) → 리미터.

### 5-3. BGM 선정

- **조건**: 저작권 걱정 없는 음원만(로열티 프리, 상업·비상업 영상 사용 허용 확인). 출처·라이선스를 크레딧 문서에 기록한다. 예: YouTube 오디오 보관함, 팀이 이용권을 가진 음원 서비스.
- **느낌**: 100~115 BPM, 어쿠스틱 기타·피아노·가벼운 플럭(pluck) + 손뼉·셰이커 정도의 가벼운 타악기. 밝지만 시끄럽지 않은 곡. 중식당 느낌을 내려고 전통 악기를 과하게 넣지 않는다(고정관념처럼 들릴 수 있음, 쓰더라도 한두 소리만).
- **구조가 영상과 맞는 곡**을 고른다:

  | 구간 | 음악 |
  |---|---|
  | ① 문제 | 피아노만, 조용히 (또는 음악 없이 식당 소음만) |
  | ② 제목 | 곡이 열리는 지점(드럼·베이스가 들어오는 곳)을 제목 컷에 맞춤 |
  | ③ 시연 | 같은 곡을 낮게 깔고, 키오스크 음성이 나올 때 더 낮춤 |
  | ④ 검증 | 리듬이 조금 단단해지는 부분 |
  | ⑤ 마무리 | 따뜻하게 커졌다가 로고에서 깔끔하게 끝나는 엔딩 |

- 한 곡으로 끝내는 것이 가장 좋다. 두 곡을 쓰면 ②나 ④의 컷에서 크로스페이드 1초.

### 5-4. 효과음 선정

적게 쓸수록 좋다. **키오스크가 실제로 내는 소리와 헷갈리지 않게**, 영상용 효과음은 모두 작고 부드럽게.

| 장면 | 효과음 | 크기 |
|---|---|---|
| 버튼 터치 | 부드러운 톡(클릭) | 아주 작게 |
| 보드 칸 ✓ | 맑은 짧은 차임 한 음 | 작게 |
| 말풍선 등장 | 가벼운 팝 | 아주 작게, 매번 넣지 않음 |
| 구간 전환 (회문 띠 와이프) | 짧은 휙(whoosh) | 중간 |
| 숫자 카운트업 끝 | 작은 딩 | 작게 |
| 주문번호 화면 | 밝은 완료음 | 중간 |
| ①·② 실사 | 식당 홀 소음(그릇·웅성임) | 아주 작게 깔기 |

- 직원 호출 장면의 알림음은 **키오스크가 실제로 내는 소리를 그대로** 쓴다(따로 효과음을 얹지 않음).

### 5-5. 삽입과 오디오 싱크 맞출 때 주의할 점

1. **키오스크 소리는 따로 녹음한다.** macOS 기본 화면 녹화(Shift+Cmd+5)는 컴퓨터 소리를 담지 못한다. OBS 같은 도구로 화면과 컴퓨터 소리를 함께 녹화하거나, 실물 키오스크를 카메라로 찍으면서 스피커 옆에 녹음기를 따로 둔다.
2. **카메라와 녹음기를 따로 쓰면 시작할 때 손뼉을 한 번 친다.** 편집에서 손뼉 소리 파형과 화면을 맞추면 끝까지 맞는다. 1분마다 어긋나지 않는지 확인한다.
3. **샘플레이트를 모두 48kHz로 통일한다.** 44.1kHz와 섞이면 길게 갈수록 소리가 밀린다.
4. **우선순위: 키오스크 음성 > 나레이션 > 효과음 > BGM.** 키오스크가 말할 때 나레이션을 겹치지 않는다. 나레이션은 키오스크 말 사이의 빈 곳에만 넣는다.
5. **덕킹(BGM 자동 낮추기)**:
   - 나레이션이 나올 때 BGM은 나레이션보다 **15~18dB 낮게**.
   - 키오스크 음성이 나올 때는 **20~24dB 낮게**(거의 안 들릴 정도). 손님 목소리도 또렷해야 한다.
   - 낮아지고 올라가는 시간은 각각 0.3초, 0.6초. 툭 끊기지 않게.
6. **효과음은 화면보다 1~2프레임 먼저.** 소리가 늦으면 사람은 어긋났다고 느낀다.
7. **끼어들기 장면은 소리를 손대지 않는다.** 직원 음성이 손님 말에 멈추는 순간이 증거다. 그 구간의 키오스크 음성·손님 목소리는 자르거나 옮기지 않는다.
8. **손님 목소리(시연자)**: 키오스크 마이크가 아니라 별도 마이크로 녹음해 또렷하게 들리게 한다. 얼굴이 나오는 시연자는 촬영·목소리 사용 동의를 받는다.
9. **최종 음량**: 온라인 영상 기준 통합 **-14 LUFS**, 최고점 **-1dBTP**. 발표장 스피커로 틀 경우 미리 한 번 틀어 보고 너무 크면 -16 LUFS 버전을 따로 만든다.
10. 마지막으로 **이어폰과 노트북 스피커 두 곳**에서 처음부터 끝까지 들어 본다. 노트북 스피커에서 나레이션이 묻히면 BGM을 더 낮춘다.

## 6. 촬영·녹화 소스와 방법

> **오늘 고친 기능(따뜻한 말투, 4명 이상 재질문, 직접 말하기, 빠른 인식, 메뉴판 수정)은 아직 Render 배포에 없다.** 시연은 로컬에서 녹화한다.

| 소스 | 방법 |
|---|---|
| 키오스크 실행 | 터미널 두 개: `npm run dev -w backend`, `VITE_RECOMMEND_LAYOUT=board npm run dev -w frontend` → Chrome에서 `http://localhost:3000` |
| 세로 화면 녹화 | 세로 모니터에 전체 화면, 또는 Chrome 개발자 도구의 기기 모드에서 1080×1920 |
| 대화 시연 | 시나리오 2-1을 **말로** 진행. 실패에 대비해 같은 답의 터치 버튼으로도 한 번 더 녹화해 둔다 |
| 끼어들기 | 직원이 질문을 읽는 도중 "새우는 빼 주세요"라고 말하는 장면을 한 테이크로 |
| 대화 원문 | `eval/live/raw/<날짜>.jsonl` (자막과 대사 확인용, 영상에 파일 화면을 보여 줄 필요는 없음) |
| 검증 화면 | `eval/sim/summary.json`, 테스트 실행 화면(`npm test -w backend` 등 통과 줄) |
| 실사 | 21인치 세로 키오스크 + 웹캠 실물, 손 클로즈업 위주 |

- **Gemini 하루 사용량**: 대화 한 번에 요청 4~6번을 쓴다. 리허설을 너무 많이 하면 녹화 때 한도가 끝날 수 있다. 녹화 전 리허설은 2~3번으로 제한하고, 시뮬레이션은 꺼 둔다(현재 꺼져 있음).
- `Ctrl+Shift+1~4` 시연 단축키는 **예전 규칙 추천 길**로 들어가므로 이번 영상에는 쓰지 않는다.

## 7. 지켜야 할 것

- **개인정보**: 얼굴은 동의한 사람만, 가능하면 손·화면 위주. 카메라 장면에 나이 숫자가 보이면 안 된다(현재 화면은 표시하지 않음). 화면 녹화에 터미널·`.env`·API 키·Render 설정 화면이 나오지 않게 한다.
- **저작권**: BGM·효과음·서체·이미지 출처를 크레딧 문서에 기록한다. 메뉴 사진은 우루루 네이버 플레이스 사진이므로 `frontend/src/prototype/menu/PHOTO_SOURCES.md`대로 엔드 카드에 출처를 넣는다. 다른 회사 키오스크·상표는 찍지 않고 그래픽으로 재현한다.
- **AI 표기**: 크레딧에 "대화 AI: Google Gemini, 음성: Google Cloud Text-to-Speech"를 넣는다. AI 생성 이미지를 쓰면 화면 구석에 "AI 생성 이미지"를 표시한다.
- **사실만**: 2-2의 "확인된 숫자"만 쓴다. 아직 확인하지 못한 것(실제 고령 손님 대상 효과 등)은 "확인 중"으로 말한다.
