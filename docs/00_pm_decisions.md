# MenuMate PM 문서 (결정 기록)

비전 AI(나이 추정) 기반 사용자 맞춤형 메뉴 추천과 쉬운 화면(UI)을 제공하는 키오스크 웹 서비스.

3명의 개발자(Frontend / Backend / AI)는 이 문서를 기준으로 작업한다. 이 문서와 각 역할의 `RULES.md`가 충돌하면 이 문서가 우선한다. **모르는 부분은 반드시 PM과 소통한 뒤 수정한다.**

마지막 갱신: 2026-10-24 (1~3차 질문과 grilling 1~4라운드 반영. 미결 사항 없음)

## 1. 한눈에 보기

| 항목 | 내용 |
|------|------|
| 형태 | 21인치 세로 모니터, 테이블 위에 올리는 대형 공용 키오스크 |
| 대상 | 55세 이상은 쉬운 화면과 음성 안내, 55세 미만은 일반 화면과 "AI와 대화하기" |
| 핵심 흐름 | 연령 인식 → 화면 자동 전환 → TTS 질문 4개(네/아니요) → 추천 3개 → 매장/포장 → 장바구니 → 결제 시뮬레이션 → 주문번호 |
| AI | 브라우저 안 On-device 추론. 얼굴 이미지는 저장하지 않음 |
| 실행 환경 | 노트북 한 대에서 프론트, 서버, DB 모두 실행. 인터넷 없이 동작 |
| 스택 | React + TS + Vite / Node.js + TS + Fastify + Prisma + SQLite / MediaPipe + ONNX Runtime Web |
| 성공 기준 | 시연에서 전체 흐름이 끊기지 않고 매끄럽게 동작 |

## 4. 계약 문서 규칙 (D37)

- 3명이 공유하는 계약은 `docs/contracts/` 한 곳에만 둔다. 다른 곳에 복사본을 만들지 않는다.
- 예정 파일: `menu-schema`, `api`, `ai-output`, `questions`, `kiosk-flow`
- 주관자가 작성하고 나머지 두 명이 검토한다.
- 바꿀 때는 3명에게 먼저 알리고 PM 승인을 받은 뒤 반영한다. 반영 후 이 문서의 결정 기록에도 남긴다.

## 5. 소통 규칙

- 모르는 것, 다른 역할에 영향을 주는 변경은 **구현 전에** PM에게 묻는다.
- 우선순위가 충돌하면 "시연에서 전체 흐름이 끊기지 않는가"(D15)를 기준으로 PM이 판단한다. 정확도나 기능 추가보다 흐름 안정성이 우선이다.
- 새 외부 서비스, 새 라이브러리 계열, 개인정보에 닿는 변경은 PM 승인이 필요하다.
