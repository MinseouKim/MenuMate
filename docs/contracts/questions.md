# 계약: 취향 질문과 추천 점수

- 주관: AI / 검토: Frontend, Backend / 승인: PM
- 상태: v1 확정 (2026-10-24)
- 관련 결정: D5, D6, D14, D19, D28

## 원칙
- 질문은 4개, 답은 `yes` / `no` / `skip` 세 가지다. 화면에서는 "네", "아니요" 버튼과 "그냥 메뉴 볼래요"(질문 종료, D17)를 쓴다. `skip`은 TTS나 화면 오류 등으로 답 없이 넘어갈 때만 쓴다.
- 55세 이상/미만 모두 같은 질문, 같은 점수다 (D19). **연령대는 추천 계산에 넣지 않고 서버로 보내지도 않는다.**
- 질문 데이터의 원본은 Backend 코드 한 곳이다. 프론트는 `GET /api/questions`로 받아 화면과 TTS에 쓴다. 프론트와 AI 코드에 질문 문구를 복사하지 않는다.

## 질문 목록

| 순서 | id | 화면/음성 문구 | yes 점수 | no 점수 |
|------|----|---------------|---------|---------|
| 1 | `q_spicy` | 매운 음식도 괜찮으세요? | spicy +2, mild -1 | spicy -3, mild +1 |
| 2 | `q_soup` | 따뜻한 국물이 있는 음식이 좋으세요? | soup +2 | soup -1 |
| 3 | `q_soft` | 부드럽게 드실 수 있는 음식이 좋으세요? | soft +2 | (변화 없음) |
| 4 | `q_hearty` | 든든하게 드시고 싶으세요? | hearty +2 | hearty -1 |

`skip`은 점수에 아무 영향이 없다.

## 추천 점수 계산

```
prefs[tag]  = 각 답의 점수를 태그별로 더한 값 (없으면 0)
score(menu) = Σ prefs[t] (t ∈ menu.tags)  +  menu.priority × 1.5
```

- `isAvailable = false` 메뉴는 제외한다.
- 정렬: `score` 내림차순 → `priority` 내림차순 → `sortOrder` 오름차순 → `id` 오름차순. 같은 입력이면 항상 같은 결과가 나와야 한다.
- 상위 **3개**를 돌려준다.
- 각 결과에 `reasons`를 붙인다: 점수에 +로 기여한 태그 목록(기여가 큰 순), 그리고 `priority > 0`이면 `"store_pick"`.
- 모든 답이 `skip`이거나 질문을 중간에 종료해도 계산은 동작해야 한다 (그때는 priority와 정렬 규칙만으로 3개).

## 화면에 보일 추천 이유 문구 (프론트가 reasons를 문구로 바꿈)

| reason | 문구 |
|--------|------|
| `spicy` | 매콤한 맛 |
| `mild` | 순한 맛 |
| `soup` | 따뜻한 국물 |
| `soft` | 부드러운 식감 |
| `hearty` | 든든한 한 끼 |
| `store_pick` | 사장님 추천 |

## TTS 규칙 (AI 담당, D28)
- 질문 화면에 들어오면 문구를 한 번 읽는다. 화면에 "다시 듣기" 버튼을 둔다.
- 읽는 중에 답 버튼을 누르면 읽기를 멈추고 다음 질문으로 간다.
- 질문 외 안내 문구(시작 인사, 추천 결과 안내 등)는 Frontend가 정하고 같은 TTS 모듈로 읽는다.

## 바꾸는 절차
문구나 점수를 바꾸려면 AI가 이 문서를 고치고, Backend가 같은 값으로 코드와 테스트를 고친 뒤 PM이 승인한다.
