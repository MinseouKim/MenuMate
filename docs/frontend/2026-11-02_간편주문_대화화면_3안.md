## 답변이 정해진 것이 아님을 확인

같은 첫 인사 뒤에 손님 말만 바꿔 서버 `/api/chat`에 보냈다.

| 손님 말 | 직원 AI 답 | 파악한 조건 |
|---|---|---|
| 혼자 왔어요. 매운 거 아주 좋아해요 | 화끈하게 매운 요리로 준비해 드릴게요, 면이나 밥 중에서 어떤 걸로 드시겠어요? | party 1, spicy 3 |
| 넷이서 왔고 아이가 있어서 안 매운 걸로요. 새우는 빼 주세요 | 아이와 함께 드시기 좋은 안 매운 요리로 골라드릴게요. 어떤 종류가 좋으신가요? | party 4, spicy 0, exclude 새우 |
| 둘이요. 딤섬이 먹고 싶은데 예산은 1인당 2만원이에요 | 둘이서 딤섬 좋죠! 매운맛도 괜찮으신가요? | party 2, kind 딤섬, budget 20000 |

화면의 버튼(터치 답변, 선택 카드, 종류 그림)은 **말 대신 보내는 문장**일 뿐이고, 어떤 버튼을 보여 줄지는 직원 AI의 마지막 질문을 읽어 정한다(`layout.ts` `askingOf`).

## 질문과 터치 답 버튼 맞추기

배포 서버 Gemini와 7가지 흐름(터치만 3, 말 4)을 돌려 질문 12개를 모았더니 2개에서 버튼이 엇나갔다. "얼마나 매운 걸로 드릴까요? 면이나 밥 중 어떤 걸로 원하세요?", "그럼 안 매운 국물 요리로 원하시는 면이나 밥 종류가 있으실까요?"는 종류를 묻는데 매운맛 버튼이 떴다(앞에 나온 '매운'을 먼저 잡음). 매운 걸 이미 말한 손님이 "매운 건 못 먹어요"를 눌러 조건이 뒤집힐 수 있었다.

- 서버: 응답에 `asking`(party·spicy·kind·exclude·other)을 더하고 "reply 질문과 꼭 일치"하도록 프롬프트에 적었다. 물음표는 답 끝에 한 번만. 화면은 이 값을 먼저 쓴다.
- 화면(옛 서버 대비): `askingOf`가 마지막 물음 문장에서 가장 뒤에 나온 낱말로 고른다. "드시면"의 '면'은 종류로 보지 않고, "매운 거 못 드시는 분"은 매운맛으로 본다. 위 12개 모두 맞게 나온다.
- 그 밖(other) 질문의 버튼을 인원·매운맛 섞음에서 **네, 좋아요 / 아니요, 다른 걸로요 / 잘 모르겠어요 / 아무거나 추천해 주세요**로 바꿨다.
- 서버 `asking`은 배포 뒤 실제 Gemini로 다시 확인해야 한다.

## 같이 고친 것

- 첫 인사가 인원을 묻지 않고 "따뜻한 국물 어떠세요?"로 끝나는 경우가 있어, 프롬프트에 "첫 인사 뒤 반드시 인원을 묻고, 인원을 모르면 '아무거나'에도 인원 하나만 묻는다"를 추가(`backend/src/chat.ts`). 배포 반영은 다음 PR.
- `vite.config.ts`: `DEV_PROXY_TARGET`으로 개발 프록시를 배포 서버로 돌릴 수 있게.
