# MenuMate Backend v1 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `docs/contracts/api.md`의 엔드포인트 전부, 추천 점수, 결제 시뮬레이션, 주문번호, 메뉴 시드를 갖춘 오프라인 Fastify 서버를 `backend/`에 만든다.

**Architecture:** 순수 함수(추천 계산, 시드 검증, 날짜·주문번호 계산)와 DB를 쓰는 서비스(메뉴, 주문, 결제)를 나누고, `buildApp(deps)`가 Fastify 인스턴스를 만든다. 테스트는 vitest + Fastify `inject`로 실제 SQLite 테스트 DB에 대고 돌린다. 시계(`now`)와 결제 게이트웨이는 주입해서 날짜 리셋과 실패를 테스트한다.

**Tech Stack:** Node.js ≥22, TypeScript, Fastify 5, @fastify/static, Prisma 6 + SQLite, vitest, tsx

**Spec:** `docs/00_pm_decisions.md`, `backend/RULES.md`, `docs/contracts/api.md`, `docs/contracts/menu-schema.md`, `docs/contracts/questions.md`, `docs/env-guide.md`

## Global Constraints

- `backend/` 밖은 고치지 않는다 (이 계획 파일만 예외). 루트 `package-lock.json`은 커밋하지 않는다.
- 얼굴, 나이, 연령대 컬럼·필드·로그는 어디에도 없다 (D2, D47).
- 금액은 원 단위 정수. 부동소수점 금지 (추천 `score`만 `priority × 1.5` 때문에 소수 가능).
- 외부 API, CDN, 인터넷이 필요한 런타임 의존 금지 (D32).
- SQLite 전용 기능을 쓰지 않는다. enum 대신 문자열 + 코드 검증.
- 설정은 `backend/.env`에서만 읽는다. 경로는 `backend/` 기준 상대 경로, `/` 구분자.
- 에러 응답: `{ "error": { "code", "message" } }`, message는 화면용 한국어.
- 실행 스크립트는 `npm run`만 쓴다. 셸 스크립트 금지 (Mac/Windows 공통).

## Review Focus

1. Prisma가 SQLite 상대 경로를 `prisma/` 기준으로 해석함 → `DATABASE_URL=file:./data/menumate.db`가 `backend/data/menumate.db`에 생겨야 한다 (Task 1 래퍼 테스트).
2. 결제 요청 두 개가 동시에 같은 주문에 오면 주문번호가 두 번 발급되면 안 된다 → 하나만 `success`, 하나는 `ORDER_ALREADY_PAID` (Task 6).
3. 문자열 숫자(`"quantity": "2"`)나 소수(`2.5`)가 Fastify 기본 형 변환으로 통과하면 안 된다 → 400 (Task 5).
4. 시드 재실행 시 기존 주문이 메뉴 FK 때문에 시드를 막으면 안 된다 → 주문 항목은 이름·단가 스냅샷을 갖고 메뉴 FK가 없다 (Task 7).
5. `MODEL_DIR`, `FRONTEND_DIST`, `MENU_IMAGE_DIR` 폴더가 없어도 서버가 뜬다 (Task 8).
