# AI 규칙

기준 문서: [`docs/00_pm_decisions.md`](../docs/00_pm_decisions.md). 이 문서와 충돌하면 PM 결정이 우선한다. 괄호 안 번호(D00)는 그 문서의 결정 번호다.

## 1. 담당 산출물
1. **AI 모델·파이프라인 입출력 명세**
2. **브라우저 추론 모듈**: 프론트가 import해서 쓰는 얼굴 검출 + 나이 추정 모듈
3. **TTS 모듈**: 질문을 읽어 주는 음성 안내
4. 주관 계약: `docs/contracts/ai-output` (AI 출력 형식), `docs/contracts/questions` (질문 4개와 태그 점수)
5. 공동 작업: 환경 변수 관리 가이드의 AI 모델 경로, 시스템 아키텍처 구상도의 AI 부분

## 2. 실행 위치와 프라이버시 (D2, D10, D27)
- 추론은 **브라우저 안에서 On-device**로 한다 (WebAssembly/WebGPU). 서버로 영상이나 이미지를 보내지 않는다.
- 얼굴 이미지는 메모리에서만 처리하고 추론 직후 폐기한다. 디스크 저장, 로그 출력, 디버그 덤프, 캡처 금지.
- 인터넷 없이 동작해야 한다 (D32). 모델 파일과 WASM 파일은 CDN이 아니라 프로젝트 로컬에서 불러온다.
- Mac에서 개발하고 나중에 gram(Windows, 외장 GPU 없음)으로 옮긴다 (D22). WebGPU가 없을 때 WASM(CPU)로 돌아가는 경로를 반드시 둔다.

## 3. 모델 (D35)
- **얼굴 검출**: MediaPipe Face Detector
- **나이 추정**: ONNX Runtime Web 위에서 후보 2개를 비교해 **10/26(월)까지** PM에게 보고하고 확정한다.
  - 비교 기준: 55세 경계(50~60세) 판정 정확도, Mac에서의 처리 속도, 모델 크기, 라이선스
  - 일부 후보는 "비상업 연구용" 라이선스다. 전시에는 쓸 수 있어도 상용화 때 바꿔야 할 수 있으므로 결과에 꼭 적는다.
- 확정한 모델의 이름, 버전, 출처, 라이선스, 크기를 PM 문서에 기록한다.
- 모델 파일은 저장소에 커밋하지 않는다. 받는 방법과 둘 경로를 문서로 남기고, 경로는 환경 변수로 읽는다.

## 4. 판정 규칙
- 출력 최소 필드: `face_detected`, `is_senior`(55세 이상 여부, D3), `confidence`. 정확한 형식은 `ai-output` 계약에서 확정한다.
- 원본 나이 숫자는 내부 판정에만 쓰고 모듈 밖으로 내보내지 않는다.
- **연속 N프레임이 같은 판정일 때** 확정한다. 프로토타입 기준은 5프레임, 신뢰도 0.7이다. 실제 웹캠과 설치 위치(모니터 위, D31)에서 측정해 값을 조정하고 PM에게 보고한다.
- 얼굴이 보인 뒤 **8초 안에 확정이 안 되면** "미확정"을 알려 프론트가 일반 화면으로 가게 한다 (D16).
- 여러 명이 보이면 **가장 크게 잡힌 얼굴 1명**만 판정한다. 확정 후 그 세션에서는 재판정하지 않는다 (D18).
- 신뢰도가 낮거나 얼굴이 없으면 확정하지 않는다.
- 입력 프레임 형식, 해상도, 처리 주기(FPS), 지연 시간 목표를 명세에 적는다.

## 5. 음성 (D14, D28)
- 질문은 **TTS로 읽고, 답은 프론트의 큰 "네/아니요" 버튼**으로 받는다.
- TTS는 **기기에서 직접 돌아가는 음성만** 쓴다. Chrome의 "Google 한국의"처럼 네트워크를 쓰는 음성은 제외하고, macOS의 Yuna 같은 OS 내장 한국어 음성을 쓴다. 브라우저에서 고를 때 로컬 음성인지 확인하고, 없으면 PM에게 알린다.
- gram(Windows)에서도 쓸 수 있는 한국어 내장 음성을 확인해 둔다.
- 고령층이 듣기 쉽게 느린 속도로 읽는다.
- On-device 음성 인식(STT)은 2차 범위다. 지금은 만들지 않는다.

## 6. 질문과 취향 분석 (D14, D19)
- 취향 분석은 규칙 기반이다: 질문 4개 → 네/아니요 → 태그 점수. 55세 이상/미만 모두 같은 질문을 쓴다.
- 질문 문구와 태그 점수표는 `docs/contracts/questions` 한 곳에만 두고, Frontend와 Backend가 같은 문서를 쓴다.

## 7. 시연 대비 (D24, D30)
- 프론트가 "55세 이상 강제 인식" 키보드 단축키를 붙일 수 있게, 추론 결과를 덮어쓰는 진입점을 모듈에 둔다.
- 전시장 조명을 가정해 어두운 곳, 역광, 안경, 마스크에서 판정을 확인한다.

## 9. 소통
- 입출력 필드를 추가하거나 바꾸면 Frontend, Backend에게 알리고 PM 승인을 받는다 (D37).
- 카메라, 설치 각도, 노트북 사양처럼 하드웨어 정보가 필요하면 PM에게 묻는다.
- 성공 기준은 정확도 단독이 아니라 "시연에서 전체 흐름이 매끄럽게 이어지는 것"이다 (D15).
