# 웹캠 실측 기록

판정 기준값(`stableFrames`, `minConfidence`, `noFaceGraceMs`)을 정하기 위한 실제 웹캠 측정. 근거가 충분할 때만 기본값을 바꾼다.

## 1차 (2026-10-25, 사용자)
- 조건: Mac 내장/외장 웹캠 1280×720, 데모 기본 설정(5프레임 · 0.7 · 8초 · 6fps · 유예 0), 받은 로그 4줄

```
12:14:51 카메라 1280x720
12:14:55 detecting non_senior run 1/5 elapsed 0
12:14:55 detecting non_senior run 2/5 elapsed 239ms
12:14:55 detecting non_senior run 3/5 elapsed 406ms
12:14:55 detecting non_senior run 4/5 elapsed 574ms
```

### 알 수 있는 것
- **실시간으로 돈다**: 프레임 간격 239 → 167 → 168ms. 첫 간격만 조금 길고 이후 목표 6fps(167ms)를 지킨다. 검출 + 후보 B 추론이 한 프레임 안에 끝난다.
- **판정이 흔들리지 않는다**: 4프레임 연속 같은 연령대(non_senior). 이 사람(55세 미만으로 추정)에게는 5프레임 기준이 0.7초 안에 채워질 속도다.
- **`low_confidence` 없음**: 이 거리·조명에서는 검출 점수 × 얼굴 크기 보정이 0.7을 넘는다.
- **`no_face` 없음**: 이 4프레임 동안은 검출이 깜빡이지 않았다.

### 부족한 것
- `decided` 줄이 없다. 5번째 프레임(약 0.74초)에서 나와야 하는데, 복사가 잘렸는지 그 전에 얼굴이 빠졌는지 알 수 없다. → 데모에 **"로그 전체 복사"** 버튼을 추가했다.
- 프레임별 신뢰도가 0.7보다 얼마나 높은지 모른다 (`detecting`에는 신뢰도가 없고 `decided.confidence`에 평균이 나온다).
- 55세 이상 얼굴, 경계 나이, 고개 돌림, 거리 변화, 자리 이탈(no_face), 타임아웃을 보지 못했다.
- 백엔드(webgpu/wasm), 노트북 기종이 없다.

### 결론
근거 부족. **기본값 유지를 제안한다: stableFrames 5, minConfidence 0.7, noFaceGraceMs 0.**

## 2차 요청 (사용자가 할 순서, 약 5분)
준비: `npm run models:setup -w ai` → `npm run demo -w ai` → http://localhost:5175/demo/ → "카메라 켜기". 실제 설치처럼 웹캠은 모니터 위, 사람은 화면 앞 약 1m.
각 항목 시작 전에 `reset()`을 누른다.

1. **정면** 10초 서 있기. 3번 반복 (매번 `reset()`).
2. **고개 돌리기**: 정면에서 시작해 10초 동안 좌우로 천천히 고개를 돌린다.
3. **자리 비우기**: 정면 2초 → 화면 밖으로 2초 나갔다가 → 다시 정면 5초.
4. **거리**: 0.5m, 1.5m, 2m에서 각각 정면 5초 (거리마다 `reset()`).
5. **고령 얼굴 대용**: 휴대폰에 60~70대 인물 사진을 크게 띄워 카메라 앞 약 50cm에 10초. (55세 이상인 분이 계시면 그분이 1번을 해 주시면 더 좋음)

끝나면 **"로그 전체 복사"**를 눌러 붙여 주세요(설정·백엔드·추론 간격이 함께 복사됨). 복사가 막히면 버튼 아래 나타나는 칸의 내용을 복사하면 됩니다. 노트북 기종과 웹캠(내장/외장)도 적어 주세요.

### 2차 로그로 정할 것
| 값 | 판단 기준 |
|----|-----------|
| `noFaceGraceMs` | 2번·4번에서 얼굴이 계속 있는데 `no_face`가 끼면 0.5초(500)로 올린다 |
| `minConfidence` | 4번에서 1.5m 이내인데 `low_confidence`가 잦으면 낮추고, 2m에서도 확정되면 그대로 |
| `stableFrames` | 1번·5번의 확정 시간이 2초를 넘거나, 연령대가 섞여 나와 확정이 늦으면 조정 |
