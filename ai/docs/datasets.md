# 리뷰 학습 데이터 조사 (D74, D75)

- 작성: AI / 상태: 초안 (2026-10-27)
- 원칙: **원본 데이터는 커밋하지 않는다.** 받는 방법(`ai/engine/`의 받기 스크립트)과 출처·라이선스만 남긴다. 엔진 결과(`backend/engine/menu-features.json`)는 메뉴별 통계값만 담고 리뷰 문장은 담지 않는다.
- 로그인·신청이 필요한 데이터는 받지 않았다. 링크만 적는다 (사용자가 직접 받음).

## 1. 결론
- **리뷰 쓴 사람의 나이가 붙은 한국어 음식점 리뷰 데이터는 찾지 못했다** (GitHub, Hugging Face, Kaggle, AI-Hub, 공공데이터포털).
  → 연령대 적합도는 **공공 통계(연령층별 다빈도 음식 섭취 비율) + 특징 × 연령대 가중치 규칙**으로 만든다 (`engine.md`에 근거).
- **광고 표시 데이터**: "체험단/협찬" 라벨이 붙은 공개 데이터는 없다. 대신 **배달앱 "리뷰 이벤트"(별점 5점 + 사진 보상) 참여 라벨**이 있는 데이터(②)가 있어, 대가를 받고 쓴 리뷰를 걸러 내는 분류 모델 학습에 쓴다.
- 로그인 없이 받은 3개(①②③)로 엔진 v1을 만든다 (D80: 데이터를 제때 못 받으면 GitHub 데이터만으로).

## 3. 데이터별 쓰임

| 엔진 요소 | 쓰는 데이터 | 방법 (자세한 내용은 `engine.md`) |
|-----------|-------------|-------------------------------|
| 메뉴 특징 (맵기·부드러움·양·국물·짠맛 등) | ① + ② 리뷰 본문 | 메뉴명이 나온 문장에서 특징 표현을 세어 0~1로 |

## 4. 한계 (꼭 알아야 할 것)
- **나이 정보가 붙은 리뷰는 없다.** 연령대 적합도는 "그 연령층이 실제로 자주 먹는 음식인가"(③)와 규칙의 조합이지, "그 연령대 손님의 평"이 아니다. 화면 문구 `age_fit`("비슷한 연령대 손님이 좋아해요")은 이 근거에 맞게 다듬어야 한다 (`questions-v2.md`).
- **③의 가공 문제**: 설명에는 65세 이상이 있다고 되어 있지만 CSV에는 **65세 이상 행이 없고**, 연령층마다 이름 없는 묶음이 3개씩 있다(전체·남자·여자로 추정). 3개 묶음의 평균을 쓰고, 55세 이상은 50~64세 값으로 대신한다. 원본(국민영양통계 사이트)으로 확인할 수 있으면 나중에 교체한다.
- **② 라벨의 뜻**: "광고/체험단"이 아니라 "리뷰 이벤트(별점 5점·사진 조건 보상)의 영향을 받은 리뷰"다. 대가성 리뷰라는 점은 같지만 블로그 체험단 글과 문체가 다르다. `3` 값의 의미는 문서에 없어 학습에서 뺀다.
- **①의 출처**: 공개 웹 크롤링 (제작자는 비상업 공정 이용이라고 밝힘). 전시는 비상업이라 사용 가능하지만, **상업화 때는 ①을 빼거나 재검토**해야 한다. CC BY-NC-SA라 `menu-features.json`에 출처 표시를 넣는다.
- 우리 메뉴 26개 중 언급이 적은 것: LA갈비(①109건, ②0건), 두부부침(44건), 호박죽(130건), 돌솥비빔밥(138건, "비빔밥"으로 합쳐 셀 수 있음). 이런 메뉴는 특징을 기본값 쪽으로 당긴다.
